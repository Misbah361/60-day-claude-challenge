# Day 7 – Claude Counter & My Claude Usage Strategy

## What I Did
Installed the Claude Counter browser extension (loaded manually from GitHub) to track my token usage and session limits directly on claude.ai. Then used a custom "Claude Usage Strategy" prompt to get a personalized recommendation on which Claude model and effort level to use for different tasks.

## Part 1: Installing Claude Counter
Steps taken:
1. Downloaded the `claude-counter` repo from GitHub as a ZIP
2. Extracted the folder
3. Enabled Developer Mode in Edge (`edge://extensions`)
4. Clicked "Load unpacked" and selected the extracted folder
5. Confirmed it works on claude.ai — shows Session % used, Weekly % used, and time until reset

![Claude Counter working on claude.ai](screenshot-counter.png)

## Part 2: My Claude Usage Strategy

### The Prompt I Used
I used a structured prompt that asks Claude to act as a Claude AI Expert and Productivity Consultant, gather info about my situation, and generate a personalized model/effort strategy.

### My Answers
1. **Situation:** Student
2. **Primary activities:** Coding, Learning Support, Career Prep, Research
3. **Usage frequency:** Daily
4. **Output types needed:** Mix of fast answers, learning support, coding help, and deep research

### My Personalized Claude Strategy (Generated by Claude)

**Recommended Primary Model:** Claude Sonnet 5

**Why it fits me:** As a daily-use student juggling coding, learning, career prep, and research, Sonnet gives ~90% of top-tier quality without burning through usage limits as fast as Opus would.

**Model breakdown:**
- **Haiku** → quick fact lookups, syntax reminders, fast rewording
- **Sonnet** → daily default: coding help, concept explanations, resume drafts, GitHub docs
- **Opus** → deep research synthesis, hard debugging, big career/architecture decisions

**Effort levels:**
- **Low** → quick lookups, formatting tweaks
- **Standard** → my default for almost everything
- **High** → multi-step tasks, resume/career docs, comparing strategies
- **Max** → rare, high-stakes research or big-picture decisions

**My Workflow Table:**

| Task | Best Model | Best Effort | Reason |
|---|---|---|---|
| Daily coding help | Sonnet | Standard | Fast enough for daily iteration |
| Learning new AI/ML concepts | Sonnet | Standard → High | High effort adds depth + examples |
| GitHub documentation | Sonnet | Standard | Structured writing, low reasoning load |
| Resume / career docs | Sonnet | High | Public-facing, quality matters |
| Deep research | Opus | High → Max | Needs synthesis across many angles |
| Quick fact-checks | Haiku | Low | Speed over depth |
| LinkedIn post drafting | Sonnet | Standard | Good quality without overkill |
| Hard, stuck bugs | Opus | High | Escalate after Sonnet fails twice |

**Biggest mistakes to avoid:**
- Using Opus for everyday tasks (wastes usage limit)
- Defaulting to Max effort (slower, rarely needed)
- Sticking to one model/effort for everything
- Not escalating to a stronger model when stuck

**Final Recommendation:** If I could only use ONE model + ONE effort level, it would be **Claude Sonnet at Standard effort** — the best all-round balance of speed, capability, and usage efficiency for a daily student workflow.

## Key Learnings
- Claude Counter is genuinely useful for managing usage — I can now see exactly how close I am to my session/weekly limits before hitting a wall.
- Model + effort selection isn't one-size-fits-all — matching the tool to the task (Haiku for speed, Sonnet for daily work, Opus for hard problems) is a more efficient way to work than always reaching for the "best" model.
- Having a documented personal strategy makes it easier to decide in the moment instead of guessing each time.

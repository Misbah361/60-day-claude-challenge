# Day 3 — Role-Based Prompting

## 🎯 Task
Explore how assigning a role/persona to Claude changes its responses, using the same question across three conditions: no role, Founder persona, and Developer persona.

## ❓ Question Used
"How should I structure my next 3 months?"

## 1️⃣ No Role Assigned
**Prompt:** "How should I structure my next 3 months?"

**Output summary:** Claude offered multiple possible directions to choose from — semester-focused, AI/coding skill-focused, and career portfolio/resume-focused — leaving the goal-setting up to me.

## 2️⃣ Founder Persona
**Prompt:** "You are a startup founder. How should I structure my next 3 months?"

**Output summary:** Claude gave a business-outcome-driven, sequential 3-month plan:
- Month 1 — Validate the problem, not the product
- Month 2 — Build the smallest thing that tests the riskiest assumption
- Month 3 — Get traction and learn what's repeatable

## 3️⃣ Developer Persona
**Prompt:** "You are a software developer. How should I structure my next 3 months?"

**Output summary:** Claude gave a craft/skill-driven, sequential 3-month plan:
- Month 1 — Deepen a focused skill area
- Month 2 — Build something real with it
- Month 3 — Make it visible and get feedback

## 📊 Comparison

| | No Role | Founder | Developer |
|---|---|---|---|
| Framing | Multiple open paths | Business milestones | Skill/portfolio milestones |
| Vocabulary | Neutral | MVP, customers, traction | Source code, deploy, PR |
| Structure | Options-based | 3-month sequential plan | 3-month sequential plan |
| Assumed goal | None — left to me | Building a company | Building technical expertise |

## 💡 Key Learning
Assigning a role sharpens Claude's focus and removes ambiguity. Without a role, Claude hedges and offers choices. With a role, it commits to a confident, specific framework — even though two different roles can produce completely different (but equally valid) plans for the same question.
